# LiftUp Android setup

Updated November 4, 2026. This records implementation and build instructions. Device checks must be recorded separately before declaring the Android release complete.

## Application

- App name: LiftUp.
- Application ID: com.liftup.gymtracker.
- Source: frontend/src-capacitor/android.
- Web assets: frontend/src-capacitor/www, generated by Quasar and excluded from Git.
- Native dependencies: pinned in frontend/src-capacitor/package.json and its lockfile.
- Backend: https://liftup-ldlv.onrender.com/. Database credentials stay on Render.
- Test device: Samsung SM-A736B, Android 16 / API 36, connected by USB.

The APK bundles the Vue interface, fonts, exercise illustrations, pose model and WASM runtime. It does not load the website through Capacitor server.url. Server-backed features require internet access.

## Build tools

Use JDK 21 and Android SDK platform 36 with the generated Gradle wrapper. Android Studio can supply the JDK and SDK. Alternatively, official Android command-line tools and a compatible JDK can build the APK directly.

This workstation uses verified portable Temurin JDK 21 and Google Android tools under the ignored .tools folder. Build commands detect these tools without modifying the system Path. On another workstation, set JAVA_HOME and ANDROID_HOME to the installed tools. Install platform-tools, platforms;android-36 and the required Android build tools, and accept the SDK licenses.

Install project dependencies first:

```powershell
cd frontend
npm ci
npm --prefix src-capacitor ci
npm run build:android
```

The build prepares exercise/pose assets, compiles Quasar in Capacitor mode, syncs the native project and runs Gradle assembleDebug. The installable test output is artifacts/android/LiftUp-debug.apk. It uses a development signing key.

To install on an authorized USB device:

```powershell
adb devices -l
adb install -r artifacts/android/LiftUp-debug.apk
adb shell am start -n com.liftup.gymtracker/.MainActivity
```

Keep local.properties, SDK downloads, build outputs, keystores and signing passwords out of Git.

## Signed release

Create the signing identity only once on a trusted workstation:

```powershell
node scripts/build-android.mjs --release --init-signing
```

Later builds reuse that identity:

```powershell
node scripts/build-android.mjs --release
```

The release output is artifacts/android/LiftUp-release.apk. Gradle refuses a release task without signing credentials. The release is not debuggable. The current version is 1.0.3 (version code 4); increase the version code before distributing a later update.

The generated keystore and private configuration are stored in .tools/signing, which is excluded from Git and deployment. Keep a secure backup of both files. Never upload the signing backup, keystore or password configuration to the repository or an assignment. Losing the key prevents installing future updates over this release. When restoring the backup on another workstation, update keystorePath in the private configuration to its new absolute location.

For CI, supply LIFTUP_KEYSTORE_PATH, LIFTUP_KEYSTORE_PASSWORD, LIFTUP_KEY_ALIAS and LIFTUP_KEY_PASSWORD as private environment variables. These override the local configuration. The initialization command refuses to replace an existing identity.

An installed debug build uses a different signing key. Android cannot update it directly to the release APK. Save any unfinished work and verify server records first, then replace the test build and sign in again. Subsequent releases signed with the same release key can update normally with adb install -r, preserving app data.

## Networking and sessions

The mobile-only Quasar boot file installs an Axios adapter backed by CapacitorHttp. Existing API callers keep their relative /api routes. The adapter restricts requests to the deployed LiftUp HTTPS origin and API paths, preserves server error statuses, passes bounded timeouts and does not replay failed writes. Redirects are disabled for native API calls.

Android's native cookie manager receives the server's HttpOnly session cookie. No password or session token is written to LocalStorage, Preferences or frontend configuration. Cookie response headers are omitted from the Axios response. Server session expiry, logout and revocation remain controlled by the existing backend. CORS and browser cookie protections have not been relaxed.

Private custom movement images load through the authenticated adapter. CSV and plan exports use the same transport, then write to the app cache and open Android's share sheet. Browser builds download files normally. Runtime Capacitor detection is used for these branches. Both export formats, a custom image upload/display, and a plan file import have been verified on the phone; see ANDROID_PROGRESS.md for remaining device checks.

The camera permission is declared for the existing live video detector. It is requested when the user starts camera tracking. The native app disallows cleartext/mixed content and Android backup of its app data. The launcher and launch screen use LiftUp's existing mark and lime color.

## Device acceptance checks

- Launch without the development server and sign in using an existing account.
- Save a completed set, finish the workout and retrieve it in history after refreshing/reopening.
- Confirm the same record appears on the hosted website under that account.
- Confirm logout and session expiry return to sign-in.
- Check all four navigation destinations, Android Back, keyboard placement and system-bar spacing.
- Search exercises/history, upload and reopen a private movement image, import a plan, and save/share both export formats.
- Test camera permission granted/denied, full and partial push-ups, tracking loss, review and save, and background/return behavior.
- Test interrupted network and Render's idle wake-up without duplicate saves.
- Capture real installed-app and working-feature screenshots; build output alone is not device evidence.
